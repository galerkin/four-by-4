# 프로그램 실행기의 확장 구조

## 원칙

이 앱은 특정 운동만 하드코딩한 타이머가 아니라 **프로그램 데이터를 실행하는 도구**다. 기본 4×4는 하나의 예제 프로그램이고, 타이머 엔진은 구간 개수·길이·목표가 바뀌어도 동일하게 작동한다.

```text
기본 프로그램 / 블록 편집 / JSON 가져오기
                ↓ 검증
        Program v1 (순서가 있는 steps)
                ↓ 세션 스냅샷
       시간 기반 실행기 (순수 함수)
                ↓
현재 구간 · 남은 시간 · 다음 구간 · 완료 이벤트
         ↙            ↓             ↘
      반응형 UI      알림음       브라우저 저장
```

## 주요 경계

| 파일 | 책임 |
| --- | --- |
| `src/i18n/{ko,en}.ts`, `src/i18n/index.ts` | 한국어(기준)·영어 사전. `Messages` 타입으로 두 사전의 구조를 맞추고, 컴포넌트는 `useT()`, 라이브러리 코드는 `t()`로 현재 언어를 읽음 |
| `src/lib/programs.ts` | 프로그램 스키마, 검증, 반복 확장, 기본 4×4(`norwegianProgram()`/`localizeProgram()`로 현재 언어 표시) |
| `src/lib/timer.ts` | 상태 전이, 시각 기준 경과 시간, 건너뛰기, 기록 변환 |
| `src/hooks/useWorkout.ts` | UI 시계 이벤트와 저장/복원 연결 |
| `src/lib/library.ts` | 사용자 프로그램 목록 검증·수정·개수 제한 |
| `src/lib/storage.ts` | 저장 오류 처리, 설정 검증, 최대 심박수 추정 |
| `src/components/TimerCard.tsx` | 큰 숫자 중심 실행 화면(A) |
| `src/components/ProgramEditor.tsx` | 블록 편집(B), 반복 생성, 순서 변경 |
| `src/hooks/useWakeLock.ts`, `src/lib/audio.ts` | 브라우저별 선택적 기능; 실패해도 타이머는 진행 |
| `scripts/generate-sw.mjs`, `src/hooks/usePwa.ts` | 정적 앱 캐시, 실행을 방해하지 않는 업데이트 |

운동 중 편집/프로그램 변경은 막는다. 현재 세션에는 전체 프로그램 스냅샷을 저장하므로, 나중에 프로그램을 수정/삭제하더라도 이미 작성한 기록의 시간과 이름을 바꾸지 않는다.

## Program v1 예시

```json
{
  "schemaVersion": 1,
  "id": "my-short-program",
  "name": "가벼운 움직임",
  "description": "내 페이스로 순서대로 실행",
  "steps": [
    {
      "id": "prepare",
      "name": "준비",
      "kind": "warmup",
      "durationSeconds": 60,
      "cue": "천천히 몸을 풀어요."
    },
    {
      "id": "move",
      "name": "움직이기",
      "kind": "work",
      "durationSeconds": 120,
      "cue": "편안한 속도를 유지해요."
    },
    {
      "id": "finish",
      "name": "정리",
      "kind": "cooldown",
      "durationSeconds": 60,
      "cue": "호흡을 고르며 마무리해요."
    }
  ]
}
```

- `kind`: `warmup | work | recovery | cooldown`.
- `target`은 선택사항. 필요하면 `{ "min": 60, "max": 70 }` 형태로 최대 심박수 **비율**을 지정한다. 일반 운동에 고강도 목표를 자동으로 부여하지 않는다.
- `cue`와 `description`은 빈 문자열 가능. 이름은 비어 있을 수 없다.
- 이름/설명/안내는 텍스트로 렌더링한다. 가져온 파일은 코드나 HTML로 실행하지 않는다.
- 파일 ≤100,000 UTF-8 bytes, 1~40개 구간, 각 5초~7,200초, 총 ≤6시간.
- 목표 범위 40~100%, 최소 < 최대. 각 구간 ID는 고유해야 한다.
- 반복 편집은 저장할 때 평탄화된 구간 목록으로 확장한다. 마지막 운동 뒤 회복은 생성하지 않는다.
- 가져오기는 새 프로그램 ID를 발급한다. 기존/기본 프로그램을 파일의 ID만으로 덮어쓰지 않는다.
- 이 형식이면 나중에 다른 도구나 AI가 프로그램 파일을 생성해도 같은 검증 경계를 통과하여 실행할 수 있다. 앱 안에서 AI API를 호출하지 않는다.

## 시계와 기록

`elapsedMs`는 프로그램의 시간축 위치, `activeMs`는 일시정지와 건너뛰기를 제외한 실행 시간이다. 둘을 분리해 ‘건너뛴 준비 10분’을 ‘운동한 10분’으로 기록하지 않는다.

`setInterval`은 화면을 갱신할 뿐 매 틱마다 1초를 빼지 않는다. 저장한 `anchorAt`과 현재 시각의 차이로 남은 시간을 계산한다. 백그라운드에서 여러 구간이 지나갔으면 복귀 시 현재 구간으로 바로 이동한다. 과거 알림을 연달아 재생하지 않는다.

프로그램 끝에 도달하면 세션 ID를 기준으로 기록을 한 번만 추가한다. 기록을 지운 뒤 완료 화면에서 새로고침하더라도 삭제한 기록을 다시 생성하지 않는다. 데이터는 브라우저 한 곳에서만 관리하며, 동시 여러 탭의 쓰기 충돌이나 기기 간 동기화는 지원하지 않는다.

## 다음 확장

운동 목록·랜덤 배정·좌우 쌍·구간 내부 전환은 [별도 옵션 PRD](prd-exercise-options.md)에만 정의했다. 현재 엔진에 섞지 않고 향후 `ExerciseLibrary → AssignmentPlanner → SessionPlan`으로 분리하는 방향이다. 확정 전에 데이터 스키마나 숨겨진 기능을 추가하지 않는다.

로그인·동기화·웨어러블·네이티브 알림은 별도 요구사항과 운영 비용 검토가 필요한 기능이다. 우선 정적 웹앱의 로컬 실행을 안정적으로 검증한다.
