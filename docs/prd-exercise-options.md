# 옵션 PRD: 운동 라이브러리와 좌우 균형 랜덤 배정

**상태: 후속 옵션 / 미구현 / 기본값 OFF**

이번 MVP의 구현 범위는 승인된 **A: 큰 숫자의 실행 화면 + B: 블록형 프로그램 편집**이다. 아래 기능은 사용자의 요청대로 문서에만 보관하며, 이번 앱에 운동 목록·랜덤 배정·좌우 전환·분 단위 종목 전환 UI나 실행 로직을 추가하지 않는다.

## 1. 목적

단순히 ‘고강도’라고 표시하는 대신 사용자가 미리 등록한 운동을 실제 실행 순서에 배정한다. 원하는 운동을 나중에 계속 추가할 수 있고, 한쪽만 사용하는 운동은 반대쪽과 짝을 이루어 빠뜨리지 않도록 돕는다.

### 최초 예시

- 케틀벨 스윙: 양손 / 한 팔 변형을 구분
- 케틀벨 스내치: 오른팔 / 왼팔을 사용하는 한쪽 운동
- 이후 운동 종류는 사용자가 직접 추가

예시일 뿐이며 이 종목을 무작위로 수행하는 방식의 안전성·효과를 앱이 보증하지 않는다. 탄도성 케틀벨 운동은 기술 숙련과 적절한 중량이 중요하고, 달리기·자전거 기반의 4×4 유산소 연구 결과를 동일하게 적용한다고 주장하지 않는다.

## 2. 사용자 시나리오

1. 운동 이름, 설명, 양측/편측 유형을 등록하고 사용 여부를 선택한다.
2. 실행할 프로그램에서 운동 배정 옵션을 명시적으로 켠다.
3. 운동을 시작하기 전에 생성된 전체 배정을 미리 보고 확정한다.
4. 실행 중에는 구간 시간과 함께 운동 이름, 필요한 경우 ‘오른팔 / 왼팔’을 크게 본다.
5. 사용자 선택에 따라 4분 동안 같은 운동을 하거나, 1분 슬롯마다 운동을 전환한다.
6. 한쪽 운동을 배정하면 대응하는 반대쪽도 같은 운동·같은 시간으로 함께 배정한다.

## 3. 독립적인 옵션

### A. 운동 목록 등록

- 이름, 간단한 안내, 활성/비활성, 양측/편측 유형.
- 같은 운동의 양손/한 팔 변형은 별개 항목 또는 명시적 변형으로 관리한다.
- ‘스윙’이라는 이름만 보고 한 팔인지 자동으로 추정하지 않는다.
- 등록/수정/삭제는 진행 중인 세션의 확정된 배정을 바꾸지 않는다.

### B. 랜덤 배정

- 기본 OFF. 사용자가 켠 경우에만 활성 운동 중에서 추출한다.
- 시작 전에 한 번 생성하고 세션에 결과를 저장한다. 매 렌더, 매 초, 새로고침마다 다시 추첨하지 않는다.
- 시작 전에는 ‘다시 섞기’와 수동 수정이 가능하도록 검토한다.
- 운동이 0개인 경우 설정으로 안내하고 시작을 막는다. 1개인 경우 반복될 수 있음을 표시한다.
- 중복 허용/연속 중복 회피, 라운드별 다양성 정책은 후속 구현 전에 결정한다.

### C. 좌우 짝 맞추기

- 편측 운동을 하나 뽑으면 `(운동, 오른쪽, 시간)`과 `(같은 운동, 왼쪽, 같은 시간)`을 하나의 쌍으로 취급한다.
- 반대쪽을 위해 다시 무작위로 다른 운동을 뽑지 않는다.
- **제안:** 분 단위 전환 모드에서는 쌍을 연속 배치해 미완료 쪽이 장시간 남지 않도록 한다.
- 어느 쪽부터 시작할지(오른쪽 고정 / 사용자 선택 / 세션마다 교대)는 미정이다.
- 남은 슬롯이 홀수일 때 편측 운동 하나만 배정하지 않는다. 양측 운동을 쓰거나 실행 전에 구성을 수정하게 한다.
- 건너뛰기나 중도 종료 시 ‘미완료 쪽’을 명시한다. 균형이 맞았다고 기록하지 않으며 반대쪽 수행을 강제로 요구하지 않는다.

### D. 고강도 구간 내부 1분 전환

- 기본 OFF. 사용자가 선택한 경우에만 `240초 = 60초 × 4 슬롯`으로 세분화한다.
- 상위 4분 운동·3분 회복 타이머와 하위 운동 슬롯 타이머를 분리한다.
- 고강도 총 시간, 회복 시간, 총 40분은 종목 전환 때문에 늘어나거나 줄지 않는다.
- 예시(사용자 승인 전까지 단순 예시):
  - 0:00–1:00: 케틀벨 스내치 · 오른팔
  - 1:00–2:00: 케틀벨 스내치 · 왼팔
  - 2:00–3:00: 한 팔 케틀벨 스윙 · 오른팔
  - 3:00–4:00: 한 팔 케틀벨 스윙 · 왼팔
- 60초로 나누어떨어지지 않는 사용자 정의 구간은 반올림하거나 잘라내지 않는다. 지원할 정책을 후속 결정하기 전까지 옵션을 비활성화하고 이유를 안내한다.
- 종목 교체에 필요한 준비 시간이 포함되는지, 별도 전환 시간을 둘지는 후속 결정한다. 시간을 추가한다면 ‘총 40분 유지’ 전제와 충돌하므로 별도 프로그램으로 취급해야 한다.

## 4. 실행 및 데이터 경계 (제안, 아직 스키마 변경 없음)

- 현재 `Program.steps`는 순서·시간·안내·선택적 심박수 목표를 가진 실행 데이터다.
- 후속 기능은 `ExerciseLibrary → AssignmentPlanner → SessionPlan` 계층으로 분리한다.
- 타이머 자체는 랜덤 추첨이나 좌우 정책을 알지 않고 확정된 세션 계획만 실행한다.
- `SessionPlan`은 운동 목록의 스냅샷, 슬롯별 `exerciseId / side / duration / pairId`를 포함하는 방향을 검토한다.
- 기존 v1 프로그램 JSON과 운동 기록을 깨지 않는 버전 마이그레이션이 필요하다.
- 내보내기·가져오기에서 연결된 운동 정의를 어떻게 포함할지도 결정한다.
- 일시정지, 새로고침, 백그라운드 복귀 시 운동·좌우·슬롯이 바뀌지 않아야 한다.
- iOS 웹의 잠금 화면/백그라운드 제약은 그대로다. 전환 알림이 항상 울린다고 약속하지 않는다.

## 5. 후속 구현 전 결정할 질문

1. ‘다음번에는 반대 팔’은 다음 1분 슬롯인가, 다음 4분 라운드인가? 두 모드를 모두 지원할까?
2. 편측 운동의 시작 방향은 어떻게 정할까?
3. 랜덤 배정은 중복을 허용할까? 같은 운동을 얼마나 연속할 수 있을까?
4. 스윙의 양손/한 팔 변형은 별도 운동으로 등록할까?
5. 운동 전환 준비 시간을 어떻게 확보할까?
6. 사용자가 한쪽 슬롯을 건너뛸 때 남은 짝과 기록을 어떻게 표시할까?
7. 1분 전환은 고정 60초로만 지원할까, 나중에 간격 선택도 허용할까?

## 6. 수용 기준

- [ ] 옵션 OFF일 때 현재 4×4 타이머의 결과와 동작이 변하지 않는다.
- [ ] 사용자가 운동을 추가·편집·삭제하고 활성 목록만 추첨 대상으로 고를 수 있다.
- [ ] 오른팔/왼팔은 눈에 잘 띄는 문자로 표시하며 색만으로 구분하지 않는다.
- [ ] 편측 쌍은 같은 운동·동일 시간이고, 한쪽만 계획에 남지 않는다.
- [ ] 기본 4분은 정확히 60초 × 4이고 회복은 별도로 정확히 180초다.
- [ ] 경계(59.999/60/120/180/240초)에서 슬롯 전환이 중복되거나 누락되지 않는다.
- [ ] 일시정지·새로고침·복귀 후에도 확정한 추첨 결과가 유지된다.
- [ ] 건너뛴 시간·종목·좌우는 완료한 것으로 기록되지 않는다.
- [ ] 빈 목록, 운동 하나, 홀수 슬롯, 맞지 않는 구간 길이에 대해 명확히 안내한다.
- [ ] iPhone 16 Pro Max에서 운동명·좌우·남은 시간을 스크롤 없이 읽을 수 있다.

## 7. 권장 구현 순서

운동 등록 → 수동 배정 → 좌우 쌍 정책 확정 → 랜덤 계획 생성 → 1분 슬롯 옵션 → 경계/복원/접근성 테스트. 각 단계는 독립적으로 검토하며, 이번 MVP에는 포함하지 않는다.
