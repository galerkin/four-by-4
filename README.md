# four by four

**생각은 줄이고, 움직임에 집중하는 운동 프로그램 실행기.**

노르웨지안 4×4를 첫 기본 프로그램으로 제공하는 한국어 정적 웹앱입니다. 큰 숫자의 실행 화면(A)과 블록형 프로그램 편집(B)을 조합했습니다. 데스크톱과 iPhone 16 Pro Max(440 × 956 CSS px)를 기준으로 반응형 구성했습니다.

> **웹앱:** https://galerkin.github.io/four-by-4/ · GitHub Pages의 무료 HTTPS 정적 호스팅을 사용합니다. 검증한 정적 파일만 `gh-pages` 브랜치에 게시합니다.

## 로컬 실행

Node.js **22.12 이상**이 필요합니다. `.nvmrc`는 22를 사용합니다.

```bash
npm ci
npm run dev
```

- PC: Vite가 출력하는 `http://localhost:5173`
- 같은 Wi-Fi의 iPhone: Vite의 `Network` 주소를 Safari에서 열기 (예: `http://192.168.0.10:5173`)
- 컴퓨터를 켜 두고 서버를 실행해야 합니다. 휴대전화의 `localhost`는 컴퓨터가 아니라 휴대전화 자신을 뜻합니다.
- 연결이 안 되면 같은 네트워크인지, macOS 방화벽이 Node의 로컬 연결을 허용하는지 확인하세요. 외부 포트 개방이나 터널은 필요하지 않습니다.

실제 배포 산출물과 오프라인 캐시를 확인할 때:

```bash
npm run build
npm run preview -- --port 5173 --strictPort
```

개발 서버와 미리보기 서버를 동시에 같은 포트에 띄우지 마세요. `Ctrl+C`로 종료할 수 있습니다. PWA 오프라인 캐시는 **production build에서만** 등록합니다. 개발 서버에서는 캐시로 인한 오래된 화면을 피하기 위해 등록하지 않습니다.

### iPhone 로컬 HTTP 주의점

- 로컬 Wi-Fi HTTP에서는 기본 타이머와 편집을 확인할 수 있습니다.
- **서비스 워커·오프라인 설치·화면 켜짐 유지**는 보안 컨텍스트(HTTPS 또는 같은 컴퓨터의 localhost)에 의존합니다. iPhone의 LAN HTTP에서 지원되지 않을 수 있습니다.
- Playwright WebKit의 모바일 화면 검증은 실물 iPhone의 Safari/홈 화면 앱 검증을 대체하지 않습니다.
- 소리·잠금·앱 전환·실제 홈 화면 설치는 추후 HTTPS 또는 신뢰할 수 있는 로컬 HTTPS 환경에서 실기기로 확인해야 합니다.
- 새로고침한 뒤 브라우저가 자동 소리를 차단할 수 있습니다. 진행 중 세션을 복원하면 표시되는 **‘알림음 다시 활성화’**를 누르거나 일시정지 후 재개하세요.

## 현재 기능

- 선명한 구간 색상: **준비 노랑 / 운동 녹색 / 회복·정리 빨강**. 큰 숫자와 구간 이름을 함께 표시하고 글자 대비를 검증
- 기본 4×4: 준비 10분 → 고강도 4분 × 4, 사이 회복 3분 × 3 → 정리 5분 = **40분**
- 고강도 목표는 **최대 심박수의 85–95%**, 회복·준비·정리는 60–70% 안내
- 워치 연결이나 심박수 측정 **아님**. 나이 기반 성인 추정치 또는 직접 입력한 최대 심박수로 목표 범위 계산
- 시작, 일시정지, 재개, 재시작 확인, 구간 건너뛰기 확인, 자동 전환, 짧은 알림음
- 화면 켜짐 유지 요청(지원 브라우저), 시각 기준 타이머와 새로고침 복원
- 준비/회복 시 연구 기반 코칭. 운동 구간에서는 타이머 중심으로 표시
- 프로그램 추가·수정·복사·순서 변경·구간 복제·삭제, 반복 구간 빠른 생성
- 프로그램 JSON 가져오기·내보내기. 기본 프로그램은 덮어쓰지 않고 복사
- 로컬 운동 기록: 최근 100개, 중복 방지, 일부 진행 구분, 내보내기·삭제
- 가벼운 설치형 웹앱(PWA), 온라인 최초 로딩·캐싱 후 오프라인 실행, 사용자가 선택하는 업데이트
- 운동 중 화면: 큰 남은 시간(세로로 긴 숫자), 구간 막대, 다음 할 것, 조작 버튼, 소리만 표시. 가로로 돌리면 숫자가 화면 왼쪽 전체를 차지
- 진행 색 채우기: 왼쪽→오른쪽(기본) 또는 가운데서 퍼지는 원 — 설정에서 선택
- **한국어(기본) / English**: 페이지 맨 아래 ‘English’ 또는 설정 → 언어에서 전환. 기본 4×4 프로그램 이름·안내도 함께 번역되고, 직접 만든 프로그램은 쓴 그대로 표시
- 외부 런타임 API, 계정, 데이터베이스, 분석 추적 코드 없음. 폰트도 자체 제공

## 기록과 타이머의 의미

- 기록의 ‘실제 진행 시간’은 **타이머가 실행된 시간**이며 실제 운동량·소모 칼로리·심박수 측정값이 아닙니다.
- 일시정지 및 건너뛴 시간은 제외합니다. 건너뛴 구간이 있으면 ‘일부 진행’으로 기록합니다.
- 재시작하면 현재 미완료 시도는 기록하지 않고 초기화합니다. 이전 기록은 유지합니다.
- 실행 중 브라우저를 닫거나 잠가도 복귀 시 시각 차이를 반영합니다. 실제로 운동을 멈췄다면 먼저 일시정지하세요.
- 기기의 시스템 시계를 바꾸면 경과 시간에 영향을 줄 수 있습니다.
- 동시에 여러 탭/기기에서 하나의 세션을 공동 실행하는 기능은 없습니다. **운동은 한 탭에서** 실행하세요.

## 검증

```bash
npm run check                    # lint + 단위 테스트 + TypeScript/production build
npx playwright install chromium webkit
npm run test:e2e                 # 데스크톱 Chromium + iPhone 크기 WebKit
npm audit                       # 의존성 점검
# GitHub Pages와 같은 하위 경로의 산출물 검증 (4174 포트 사용)
VITE_BASE_PATH=/four-by-4/ npm run build
npm run test:pages
# 로컬 루트 주소로 다시 볼 때
npm run build
```

E2E가 별도 production 서버를 `127.0.0.1:4173`에 열고 종료합니다. 4173은 비워 두세요. 시계를 가속하여 실제 40분을 기다리지 않고 전체 프로그램을 검증합니다.

검증 범위: 타이머 경계·복원·기록, 블록 편집·반복·파일 입출력, 저장소 오류, 심박수 추정, 키보드/명도 대비(axe), 작은 화면 및 가로 보기. 오프라인 서비스 워커는 Chromium에서 확인합니다. iPhone의 네이티브 잠금 화면 알림/백그라운드 음성/Apple Watch·Health 연동은 지원하지 않습니다.

빌드 도구의 `minimatch` 취약점 경고를 해결하기 위해 호환 API의 `11.0.3`을 override했습니다. 향후 상위 도구가 해당 수정 버전을 채택하면 제거를 검토하세요.

## GitHub Pages 업데이트

소스 변경을 `main`에 커밋하고 push한 뒤 실행합니다. 깨끗한 작업 디렉터리와 설치된 Playwright 브라우저가 필요합니다.

```bash
git push origin main
npm run publish:pages
```

린트·단위 테스트·E2E·배포 경로 검증 후 `dist/`만 `gh-pages`에 올립니다. GitHub Pages는 이 브랜치의 `/`를 게시하도록 설정합니다. 소스 브랜치/인덱스를 바꾸거나 강제 push하지 않습니다. 실제 게시 없이 점검하려면 `npm run publish:pages -- --dry-run`을 사용하세요. 실행 후 로컬 미리보기용 루트 빌드도 복원합니다.

`main` push만으로 사이트가 갱신되는 것은 아닙니다. 위 배포 명령을 실행한 뒤 GitHub의 **pages build and deployment** 결과를 확인하세요.

## 데이터와 개인정보

- `localStorage`에 프로그램, 최대 심박수 설정, 현재 세션, 기록을 저장합니다.
- 기기 간 자동 동기화가 없고, 브라우저 데이터를 지우면 사라집니다. 프로그램은 파일로 백업할 수 있습니다.
- 기록 내보내기는 JSON 보관용이며, **기록 가져오기/전체 백업 복원은 아직 지원하지 않습니다.**
- Safari와 홈 화면에 설치한 앱의 저장 영역이 다를 수 있습니다.
- 저장이 차단되거나 용량이 부족하면 경고합니다. 그 경우 현재 화면에서의 실행은 가능하지만 새로고침 후 복원을 보장할 수 없습니다.
- 서비스 워커 캐시에는 앱 파일만 들어갑니다. 브라우저가 캐시를 삭제하면 인터넷에 다시 연결해야 합니다.
